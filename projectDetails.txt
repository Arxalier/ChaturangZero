Project: Self-Play AlphaZero Agent for Chaturanga

Project Overview & Background
Chaturanga is an ancient Indian board game played on an 8x8 uncheckered grid (the Ashtapada) and is widely recognized as the common ancestor of modern Chess, Shogi, and Makruk. While it shares structural similarities with modern chess, its distinct piece movements—such as the limited diagonal step of the Mantri (Minister) and the two-square diagonal jump of the Gaja (Elephant)—create a unique tactical landscape.
This project aims to develop an artificial intelligence agent capable of mastering Chaturanga from scratch using reinforcement learning via self-play, inspired by DeepMind’s AlphaZero. Unlike traditional chess engines that rely on alpha-beta pruning and hand-crafted evaluation functions, this agent will receive no human domain knowledge beyond the fundamental rules of the game. It will learn entirely by playing against versions of itself, progressively improving its evaluation network and policy selection.
By completing this project, the students will demonstrate the ability to develop and deploy:
Rule Engine Implementation: Construct a computationally efficient, bug-free environment representing the 8x8 Chaturanga board, legal move generation, turn-taking, and terminal state validation.
AlphaZero Architecture Adaptation: Design a dual-headed deep neural network (Policy and Value heads) paired with a Monte Carlo Tree Search (MCTS) algorithm tailored to Chaturanga’s specific action space.
Self-Play Training Pipeline: Build a local training loop where the agent plays games against itself, stores state transitions in a replay buffer, and uses those games to optimize the neural network.
Resource Optimization: Scale down the standard AlphaZero parameters to ensure the entire training and execution pipeline can run successfully on consumer-grade hardware within a standard academic timeframe.
Methodology & System Architecture
The system will be split into three core pillars designed to interface seamlessly:
A. The Game Environment (Chaturanga Core)
A modular state machine will manage the board state. It encodes the 12 distinct piece types (6 for each player) into a multi-channel binary tensor (e.g., 13 channels of 8x8 matrices, including turn indicators). The move generator will strictly enforce traditional Chaturanga constraints, outputting a list of valid from-square to to-square transitions.
B. Guided Monte Carlo Tree Search (MCTS)
During gameplay, the agent will not choose moves purely at random or based on raw network output. Instead, it will use MCTS to look ahead a specified number of moves. The search tree expansion will be guided by the neural network's prior probabilities (Policy), and terminal/leaf nodes will be evaluated by the network’s predicted win probability (Value) rather than random rollouts. [1, 2]
C. Neural Network & Multi-Task Loss
A deep convolutional neural network (using a Residual Network backbone) will accept the board tensor input.
Policy Head: Outputs a probability distribution over all possible move combinations (flattened action space).
Value Head: Outputs a scalar between -1 (loss) and 1 (win) estimating the current player's position.
Loss Function: The network minimizes a combined loss function: the Mean Squared Error (MSE) of the value head plus the Cross-Entropy loss of the policy head, alongside L2 regularization to prevent overfitting.
Resource Mitigation & Feasibility
To make this project feasible for three students working with moderate computational resources (e.g., a single consumer GPU like an NVIDIA RTX 3060/4060 or a free Google Colab tier), the architecture will be scaled down using the following constraints:
Backbone Reduction: Instead of AlphaZero’s standard 20+ residual blocks, this project will utilize a lightweight 4-to-6 block architecture with a reduced hidden channel size (e.g., 64 or 128 filters).
Simulation Scaling: MCTS lookahead simulations will be restricted to 30–50 simulations per move during training, drastically reducing the time required per self-play generation.
Action Space Compression: The action space will be modeled using a simple, flattened from-square/to-square mapping (4,096 dimensions), masking out illegal indices before calculating softmax, avoiding complex relative move layers.

Project Roadmap: Chaturanga RL Agent
Team Roles Overview: (tentative, we’ll probably not follow this very strictly)
Student 1 (Game Logic): Board, piece movement, check/checkmate rules.
Student 2 (Neural Network): PyTorch architecture (ResNet), Value/Policy heads, tensor conversion.
Student 3 (Search Engine): Monte Carlo Tree Search (MCTS), tree traversal, action selection.
Student 4 (Pipeline & Ops): Self-play loop, replay buffer, training loop, evaluation tracking.
Phase 1: The Core Game Engine (Weeks 1–2)
Goal: Build a flawless, fast, and bug-free rule engine in pure Python (NumPy) before touching any AI.
[ ] Board & State: Implement the 8x8 array representation and starting positions.
[ ] Move Generation: Write logic for all 6 piece types (Pawn, Horse, Elephant, Chariot, Minister, King).
[ ] Legality Checks: Implement logic to filter out moves that leave the King in check.
[ ] Terminal States: Detect Checkmate, Baring the King, Stalemate, and a maximum-turn limit (e.g., 100 moves) to prevent infinite loops.
[ ] Unit Tests: Write tests for edge cases (e.g., "Does the Elephant correctly jump over pieces?").
Phase 2: The AI Components (Weeks 3–4)
Goal: Build the untrained "brains" of the operation. The game engine meets PyTorch.
[ ] State Representation (Student 2/4): Write the translator function that converts the 8x8 NumPy board into the 13x8x8 binary tensor.
[ ] Action Space Mapping (Student 2/4): Map every possible move to a flat array of 4,096 numbers (64 from-squares × 64 to-squares). Write the "masking" function to hide illegal moves.
[ ] The Neural Network (Student 2): Build the PyTorch ResNet model with a Policy head (action probabilities) and a Value head (win/loss prediction).
[ ] The MCTS (Student 3): Implement the search tree. Use dummy network predictions to ensure the tree expands, simulates, and backpropagates correctly.
Phase 3: The Self-Play Pipeline (Weeks 5–6)
Goal: Connect everything. The agent plays against itself and saves the data.
[ ] Self-Play Loop: Write the script where the AI plays a full game against itself using MCTS.
[ ] Replay Buffer: Store the data from these games (State Tensor, MCTS Action Probabilities, Final Game Outcome) in a memory buffer.
[ ] The Training Step: Write the PyTorch optimization loop. Pull random batches of games from the replay buffer and update the neural network's weights to minimize the loss.
Phase 4: Training & Benchmarking (Weeks 7–8)
Goal: Leave the agent to learn, fix memory leaks, and prove it is getting smarter.
[ ] Continuous Loop: Automate the cycle: Self-Play -> Train Network -> Replace Old Network -> Repeat.
[ ] Resource Optimization: If training is too slow, scale down the network (fewer ResNet blocks) or reduce MCTS simulations (e.g., 25 per move).
[ ] The Arena: Write an evaluation script to pit the trained agent against a "Random Move Bot."
[ ] Graphing: Plot the loss curves (Value Loss and Policy Loss) over time to visualize learning.
Phase 5: Final Report & Polish (Week 9)
Goal: Finalize code structure and prepare academic deliverables.
[ ] Code Cleanup: Add docstrings and comments. Ensure the GitHub repository is readable.
[ ] Results Analysis: Document how quickly the agent learned to beat the random bot, and analyze any weird/unique strategies it developed.
[ ] Final Write-up: Combine the system architecture details, training graphs, and methodology into the final project report.
